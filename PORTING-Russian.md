# PORTING.md — Руководство по переносу open-english (сокращённая версия)

> **Примечание**: это сокращённый перевод. Полное техническое
> руководство с деталями кода и подводными камнями остаётся доступным
> только на японском в [PORTING.md](PORTING.md) — сверяйтесь с ним
> перед фактическим применением любого паттерна.

Краткий обзор переиспользуемых паттернов реализации из этого проекта,
на случай переноса в другой проект:

1. **Паттерн интеграции с `aruaru-llm`**: требует поддержки CORS
   (`.with_cors()`) и штрафа за повторение
   (`generate_with_repetition_penalty`, по умолчанию 1,3) на стороне
   `aruaru-llm`, иначе браузер блокирует `fetch()`, либо жадное
   декодирование GPT-2 попадает в цикл повторений.
2. **Извлечение языка для TTS** (`extractSpeechText`): разделяет
   двуязычные строки в формате "English / 日本語" перед передачей в
   `SpeechSynthesisUtterance`, чтобы избежать прерывистого
   произношения.
3. **Набор иконок запуска** (`icons/` + `manifest.json` +
   `launchers/`): написанный вручную PNG/ICO-энкодер без внешних
   графических инструментов, плюс скрипты для `.lnk` Windows,
   `.desktop` Linux и `.app` macOS.
4. **Автообновление** (`auto-update.js` + `version.json`): простой
   опрос `buildId` каждые 5с с `location.reload()`.
5. **Статический сервер на основе RPoem** (`server/`): заменяет
   `python3 -m http.server` крейтом Rust, переиспользующим
   `static_file_handler` из `open-runo-poem-compat`.
6. **Структурная гарантия гибридных ответов** (`ensureHybridReply`):
   автоматически добавляет краткую заметку на японском, если ответ
   модели не содержит японского — без преувеличения качества перевода.
7. **Управление версиями + очистка старых версий на стороне
   браузера**: `version.json` с полем `version`, удаление собственных
   ключей `localStorage` приложения при новой версии.
8. **Мост к Google Custom Search JSON API + панель настроек в
   браузере**: учётные данные только в памяти процесса, никогда на
   диске.
9. **Установщик для Windows (Inno Setup) — реальные шаги проверки**:
   `PrivilegesRequired=lowest` против зависаний UAC,
   `MSYS_NO_PATHCONV=1` для тихой установки из Git Bash.
10. **Гео-/туристическая БД с предупреждениями о безопасности,
    зависящими от темы**: поиск по подстроке вместо точного
    совпадения; для опасных тем (например, альпинизм) всегда
    прилагать предупреждение о безопасности.
11. **Автообновление через GitHub Releases (только Windows)**: должно
    быть реализовано на нативной стороне (не в JS браузера);
    собственный запущенный .exe нельзя удалить в Windows — сначала
    запустить отсоединённый batch-скрипт, затем завершить собственный
    процесс.
12. **CSS-классам модальных окон нужны `max-height`/`overflow-y`**:
    каждый класс контейнера модального окна должен определять
    прокручиваемость, иначе длинный контент недоступен на мобильных
    устройствах.
13. **Включение Rust-сервера в Android**: делать пути переопределяемыми
    во время выполнения через переменную окружения; всегда защищать
    специфичную для Windows логику автообновления через
    `cfg!(target_os = "windows")`.

14. **Кроссплатформенное автообновление с откатом (rollback) на основе
    проверки работоспособности**: обобщить `apply_update_linux` в
    `apply_update_unix` (Linux и macOS используют одинаковую замену
    работающего бинарного файла); сохранять текущий бинарный файл
    перед применением обновления; после запуска новой версии проверять
    новый эндпоинт `/healthz` за короткое время, при неудаче —
    восстанавливать резервную копию. Android/iOS явно остаются вне
    области применения (ограничение платформы, а не упущение).
15. **Продвижение + автоматическая установка RSync**: если `rsync` не
    найден, показывать дружелюбное двуязычное сообщение ("Let's install
    RSync!") вместо сухой ошибки, затем пытаться автоматически
    установить его через цепочку менеджеров пакетов в зависимости от ОС
    (winget→choco в Windows, apt-get→dnf→pacman в Linux, brew в macOS,
    pkg в Termux/Android), и сразу запускать резервное копирование при
    успехе.
16. **Отдельная входная страница для ограниченного канала доступа**
    (например, `facebook.html` для пользователей с доступом только к
    Facebook): простая статическая страница, повторно использующая уже
    существующие в README ссылки для загрузки, с явным честным
    раскрытием того, что официальный бесплатный "zero-rated" доступ не
    достигается — это лишь альтернативная точка входа.

*(Примечание о машинном переводе: пункты 14-16 переведены самим
ИИ-агентом, без вычитки носителем языка.)*

**Важная оговорка**: этот проект — прототип Фазы 0 — качество
ИИ-ответов (на основе GPT-2), естественность синтеза речи и надёжное
соответствие уровню не гарантированы. Это также должно быть чётко
раскрыто при любом переносе.

## Шаблон: оригинальные многоязычные тесты + выбор языков + озвучивание (2026-08-22)

1. Разделить данные на два файла: задания теста и фразы для озвучивания
   служат разным целям.
2. Предоставить сводный API без текстов заданий
   (`GET /v1/world-languages`), а полный JSON загружать только при
   фактическом запуске теста.
3. Не переписывать существующий интерфейс тестов: достаточно добавить
   `<optgroup>` со значениями `world:<code>` и повторно использовать
   проверку и переход к преподавателю.
4. Ограничения на число языков задавать на уровне флажков; при
   достижении предела отключать **только неотмеченные** флажки.
5. Использовать существующий TTS, добавив лишь таблицу соответствия
   кода языка и тега BCP-47; честно указывать, что без установленного
   голоса текст только отображается.
6. Показывать тексты в `readonly`-`<textarea>` (можно копировать), а для
   сохранения использовать уже имеющийся эндпоинт, не создавая таблиц.

## Шаблон: правиловые ответы фиксированным текстом на чувствительные темы (2026-08-23)

1. Три части: функция определения по ключевым словам + таблица текстов с
   ключом по коду языка + функция, собирающая двуязычный ответ. Ставить в
   обработчик отправки **до** пути к ИИ и возвращаться из него.
2. Связывать слово-тему И слово-намерение, чтобы мимоходом сказанное
   «Иран» не перехватывало обычную беседу. В английских ключах ставить
   границу слова `\b` **только в начале**, иначе теряется
   «Zoroastrianism» (реально встреченная ошибка).
3. Более конкретные темы проверять раньше (666 до истории религий).
4. Гарантии честности писать прямо в текст: гипотезы **представлять**,
   городские легенды **называть легендами** (по возможности с техническим
   разбором, как с защитными штрихами штрихкода), совпадения **называть
   совпадениями**; «любопытные параллели» между древним текстом и
   современностью **подавать только как возможность** («так говорят
   некоторые») и никогда как исполнившееся пророчество (пример: Откровение
   13:16-17 «без начертания нельзя ни покупать, ни продавать» рядом со
   штрихкодами и онлайн-платежами вроде Amazon).
5. Фиксировать исключённые утверждения и причину — и в тексте ответа, и в
   комментарии кода («прочитать перед изменением»).
6. Нужные оговорки **не обязаны быть сухими формальными дисклеймерами**:
   лёгкая, тёплая формулировка («воспринимайте это как забавный факт, а не
   как надёжное доказательство») вполне годится, если читателю ясно, что
   ничего не доказывается. Критерий — «утверждается ли что-то как факт?»,
   **а не тон**. Но смягчение никогда не должно скатываться в обороты,
   читающиеся как утверждение («пророчество исполнилось», «это происходит
   на самом деле»).
