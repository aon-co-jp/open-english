تا پیشرفته همراهی می‌کند.

## معماری (طبق دستور کاربر، 2026-08-10)

- **سمت لینوکس (VPS)**: فقط یک سرور توزیع برای دانلود (جایی نیست که
  برنامه واقعاً در آن اجرا شود). مدیریت برنامه توسط
  [`open-easy-web`](https://github.com/aon-co-jp/open-easy-web) انجام
  می‌شود.
- **سمت دستگاه کاربر (رایانه شخصی/تبلت/تلفن)**: بخش استاتیک این
  مخزن (HTML/CSS/JS، در مرورگر اجرا می‌شود) + یک سرور بومی که به‌طور
  محلی از [`aruaru-llm`](https://github.com/aon-co-jp/aruaru-llm)
  اجرا می‌شود (که داخلاً از بک‌اندهای استنتاج `open-directx`/
  `open-cuda` استفاده می‌کند)، که کاربر خودش دانلود و اجرا می‌کند.
  مرورگر به‌صورت محلی (آنلاین یا آفلاین) به `http://localhost:4600`
  (پورت پیش‌فرض aruaru-llm) متصل می‌شود — طراحی «ترکیبی».

## دامنه فعلی (فاز ۰) — افشای صادقانه

- **کیفیت پاسخ‌های هوش مصنوعی**: `/v1/generate` از `aruaru-llm`
  تولید متن خودبازگشتی با GPT-2 (124M تا 1.5B، عمدتاً انگلیسی، بدون
  fine-tuning برای مکالمه) انجام می‌دهد. روانی یا تناسب با سطح
  تضمین‌شده نیست — این موضوع روی صفحه اعلام می‌شود، بدون اغراق. از
  2026-08-10، یک جریمه تکرار (پیش‌فرض ۱.۳) باگ حلقه تکرار بی‌نهایتی
  که قبلاً گزارش شده بود را برطرف می‌کند.
- **CORS**: از 2026-08-10 برطرف شده است — سرور HTTP از `aruaru-llm`
  اکنون هدرهای `Access-Control-*` ارسال می‌کند، بنابراین این بخش
  رابط کاربری می‌تواند از یک منشأ دیگر (یا از طریق `file://`) باز شود
  و همچنان به `http://localhost:4600` دسترسی داشته باشد.
- **انتخاب سطح**: انتخاب‌گر سطح از مبتدی تا پیشرفته در رابط کاربری
  وجود دارد، اما اجرای واقعی سطح فقط به یک دستور کوتاه در prompt
  محدود است — GPT-2 تضمینی برای رعایت آن ندارد.
- **صدا/TTS**: Web Speech API واقعی (SpeechSynthesis برای خروجی،
  SpeechRecognition برای ورودی میکروفون) متصل شده است، با تنظیم زیر و
  بمی/سرعت برای هر شخصیت.
- **حالت آموزش**: یک اسکریپت خودمعرفی قطعی (تولیدشده توسط هوش
  مصنوعی نیست) که اکنون همچنین شامل فن مکالمه مبتنی بر کلیدواژه یک
  میدکافه واقعی در آکیهابارا و یک گام که رونق فعلی فرهنگ ژاپنی در
  خارج از کشور را خلاصه می‌کند.
- **آیکون‌های راه‌انداز**: `icons/` + `manifest.json` (PWA) +
  `launchers/` امکان راه‌اندازی برنامه از یک آیکون روی دسکتاپ
  (ویندوز/مک/لینوکس) یا آیکون صفحه اصلی (اندروید/آیفون/آیپد) را
  فراهم می‌کنند.
- **به‌روزرسانی خودکار**: `auto-update.js` هر ۵ ثانیه `version.json`
  را بررسی می‌کند و هنگام تغییر شناسه build، صفحه را دوباره بارگذاری
  می‌کند. **محدودیت شناخته‌شده**: برخی مرورگرها `fetch()` فایل‌های
  محلی را تحت طرح `file://` مسدود می‌کنند — تضمین‌شده است هنگام
  سرویس‌دهی از طریق یک سرور HTTP محلی کار کند، در غیر این صورت
  به‌آرامی غیرفعال می‌شود.

برای اجرای open-english، باید دو نرم‌افزار زیر را دانلود و نصب کنید
(نیازی به ساخت از کد منبع نیست، تقریباً یک نصب تک‌ضربه‌ای).

|---|---|---|---|---|
| 1 | **خود open-english** (این مخزن — رابط کاربری استاتیک + سرور توزیع) | [open-english-install.exe](https://github.com/aon-co-jp/open-english/releases/latest/download/open-english-install.exe) | [tar.gz](https://github.com/aon-co-jp/open-english/releases/latest) | [APK](https://github.com/aon-co-jp/open-english/releases/latest) (فایل `.apk` را از فهرست دارایی‌ها انتخاب کنید) |

**افشای صادقانه**: پیوندهای "latest" در بالا همیشه به تازه‌ترین
GitHub Release اشاره می‌کنند (اگر نسخهٔ مشخص و ثابتی می‌خواهید، مستقیماً
از [صفحهٔ Releases](https://github.com/aon-co-jp/open-english/releases)
استفاده کنید). هنوز باینری از پیش ساخته‌شده برای macOS برای `aruaru-llm`
وجود ندارد (خود open-english یک tar.gz برای macOS ارائه می‌دهد، اما
`aruaru-llm` فقط برای Linux/Windows ارائه می‌شود) — روی macOS باید
`aruaru-llm` را از کد منبع بسازید.

در Windows، پس از نصب، ویژگی به‌روزرسانی خودکار داخلی
(`server/src/self_update.rs`) هنگام اجرا، GitHub Releases را بررسی
می‌کند و در صورت وجود نسخهٔ جدیدتر، به‌طور خودکار نسخهٔ قدیمی را حذف و
نسخهٔ جدید را نصب می‌کند — بدون نیاز به هیچ اقدامی از سوی کاربر.

## نحوه اجرا

۱. [`aruaru-llm`](https://github.com/aon-co-jp/aruaru-llm) را با
   `cargo run --release` اجرا کنید (پیش‌فرض `http://localhost:4600`،
   مدل پیش‌فرض اکنون `distilgpt2`).
۲. در پوشه `server/`، `cargo run --release` را اجرا کنید تا بخش
   استاتیک این مخزن در آدرس `http://127.0.0.1:4601/` سرویس‌دهی شود
   (مبتنی بر RPoem — دیگر نیازی به `python3 -m http.server` نیست؛
   پورت با متغیر محیطی `OPEN_ENGLISH_SERVER_BIND` قابل تغییر است).
۳. `http://127.0.0.1:4601/` را در مرورگر باز کنید. باز کردن مستقیم
   `index.html` از طریق `file://` هنوز کار می‌کند، اما برخی مرورگرها
   در آنجا `fetch()` را مسدود می‌کنند و به‌روزرسانی خودکار را غیرفعال
   می‌کنند — سرور مرحله ۲ توصیه می‌شود.
