## Versionless API の方針 / Versionless API policy (2026-11-25)
**日本語**: このリポジトリのAPIは **Versionless**(URL・パッケージ名に `v1` 等を付けず、互換性を壊さず足すだけで進化させる)。欄は足すだけ・足す欄は省略可能・知らない欄は無視・名前変更は新名を足して旧を非推奨に(期限は既定で6か月以上、使用0を確認してから削除)・enumは未知の値を許容・安全上の緊急修正は例外。既存の `.v1` は呼び出し側を壊さないよう当面残し、版なしの別名を追加して段階的に畳む。詳細・出典は [`runo/API-POLICY.md`](https://github.com/aon-co-jp/runo/blob/main/API-POLICY.md) 末尾。適用はこれから順に行う。
**English**: This repository's APIs are **Versionless**: no `v1` in URLs or package names; evolve by adding only, without breaking compatibility. Only add fields, new fields are optional, ignore unknown fields, rename by adding the new name and deprecating the old (default deadline 6 months or more, remove only after confirming zero use), tolerate unknown enum values, emergency security fixes are the exception. Existing `.v1` names stay for now so callers do not break; a versionless alias is added and `.v1` is retired in stages. Details and sources: the end of [`runo/API-POLICY.md`](https://github.com/aon-co-jp/runo/blob/main/API-POLICY.md). Rollout is step by step.

## API 方針: REST 全廃・gRPC / Connect へ
**日本語**: このリポジトリでは **REST API を新規に作らない**。ブラウザ・`curl` から呼ぶ API は **Connect の単純呼び出し**(`POST /<パッケージ>.<Service>/<Method>`、`content-type: application/json`)、サービス間は **gRPC / gRPC-web**。GraphQL は読み取り専用。既存の REST は触るときに移し、移したら旧経路は消す。JSON は RS-JSON(`from_str_secure` / `parse_secure`)で読む。例外は相手の規格が形を決めるもの(ACME、OAuth/OIDC のコールバック、第三者の Webhook、ヘルスチェック、静的ファイル、OTLP)のみ。迷ったら Connect。正本は [`runo/API-POLICY.md`](https://github.com/aon-co-jp/runo/blob/main/API-POLICY.md)。
**English**: This repository **does not add new REST APIs**. APIs called from browsers or `curl` use **Connect unary calls** (`POST /<package>.<Service>/<Method>`, `content-type: application/json`); service-to-service calls use **gRPC / gRPC-web**. GraphQL is read-only. Existing REST is migrated when touched and the old route is removed. Read JSON with RS-JSON (`from_str_secure` / `parse_secure`). Exceptions are only shapes dictated by someone else's standard (ACME, OAuth/OIDC callbacks, third-party webhooks, health checks, static files, OTLP). When in doubt, use Connect. Source of truth: the link above.

## 完成まで作り切る方針 / Finish everything policy (2026-11-27)
**日本語**: 全リポジトリで、**未確認は自動で確認し、未実施は実施し、未了は完成させる**(確認を求めず進める)。使用頻度が低いと判断される機能や、**1から作り直す大規模開発になる内容でも、やめずに最後まで開発・TEST・DEBUGする**(別の方式で済ませない、後回しにしない)。進め方: 調査(英語・日本語の検索とGitHub) → 設計 → 実装 → 実機/実データで確認 → 失敗は原因を直して再試験 → README・CLAUDE・PORTING・POLICY を日英で更新 → push。「できた」と書くのは実測した範囲だけ、確認できなかった所は「未確認」と正直に書く。例外(確認を取る): 元に戻せない削除、秘密の公開、所有者の認証・決済・実機操作が要るもの、利用者のシステム設定の変更。
**English**: In every repository, **verify what is unverified, do what is not yet done, and finish what is unfinished** automatically, without asking. Even features that look rarely used, or work that means **a large rewrite from scratch, are developed, tested and debugged to the end** (no substituting another approach, no postponing). Method: research (English and Japanese search plus GitHub) -> design -> implement -> verify on real devices or data -> fix causes and retest on failure -> update README, CLAUDE, PORTING and POLICY in Japanese and English -> push. Write "done" only for what was measured, and say "unverified" honestly for the rest. Exceptions that still need confirmation: irreversible deletions, publishing secrets, anything needing the owner's authentication, payment or real-device actions, and changes to the user's system settings.
## 2026-11-27 maid-cafe.tokyo の無料AI入口(ログイン必須・メモリー監視つき) / Free AI gate on maid-cafe.tokyo

**日本語**
- VS Code 拡張 maid-cafe-vsc が既定の `https://maid-cafe.tokyo` で無料AI(aruaru-llm の Translate / Generate / Ocr)を使えるよう、open-english サーバー(maid-cafe.tokyo の前面の裏、127.0.0.1:8104)に版なしConnectの門 `POST /openenglish.AiGate/<Method>` を追加した(`server/src/ai_gate.rs`)。新しいRESTは無し。aruaru-llm(127.0.0.1:4600)は外へ出さず、門を通した3メソッドだけ転送する(`/aruaru_llm.Llm/*` を前面から呼ぶと404)。
- ログイン: `RequestOtp {email}` → メールのコード → `VerifyOtp {email, code}` → AI専用トークン(7日、`Authorization: Bearer`)。発行・検証は既存 `auth.rs` を再利用(管理者限定のチェックだけ外した `request_otp_any`)。通常のログインセッションは発行しないので管理者2段階認証の迂回にならない。トークンはメモリ保持で、サーバー再起動で消える(再ログインが要る)。
- 入場制限: `/proc/meminfo` の MemAvailable を2秒ごとに測り、10秒ごとに同時実行上限を自動調整(空き<350MBで半減、>700MBかつ上限まで使用・応答60秒未満で+1、最大4)。空き<200MBは新規を即503+Retry-After、上限超えは待ち行列(8人・20秒)、あふれたら503。**「AI」と呼べるのはこの規則ベースの自動制御(AIMD)までで、機械学習ではない**。aruaru-llm 側の公平キューには `x-tenant: maid-cafe-vsc` で参加。環境変数 `AI_GATE_*` で変更可。
- 翻訳ワーカー: M2M100 418M int8(MIT)を `aruaru-translate.service`(127.0.0.1:4620、2スレッド、MemoryMax=900M)で常駐させ、aruaru-llm に drop-in `30-translate.conf` で `ARUARU_TRANSLATE_URL` を設定。実測: ワーカーRSS約670MB、導入後の空き約730〜1000MB、1文約1.5秒。
- 本番実測(2026-11-27): 未ログイン4メソッド401、偽トークン401、`.v1`404、前面から `aruaru_llm.Llm/*` 404、各ドメインの応答は入れ替え前と同一、エラーログ0。ログイン後の通し(OTP→トークン→Translate が「こんばんは。天気はかわいい。」を返す、Generate 200、空のOcr 400、空きメモリ閾値で503+Retry-After、上限1・待ち1で4同時→503×3/200×1)は、同じバイナリをVPSの127.0.0.1だけで一時起動し、SMTP未設定時だけ働く開発用のコード表示で確認。**実メールでのOTP受信は人の操作が要るため未確認**。旧バイナリは `open-english-server.before-aigate-20261127`。
- 注意(事故の記録): 一時起動を `/root` 直下で行ったところ、組み込みの部品自動更新(`component_update.rs`)が `/root/aruaru-llm`(リポジトリへのリンク)を自分の部品と見なし、本番 aruaru-llm を3回停止させた(systemdが自動再起動、ファイルの上書きは無し、一時ファイルは削除済み)。試験用の起動は部品フォルダーの無い専用フォルダーで行うこと。

**English**
- To let the VS Code extension maid-cafe-vsc use the free AI (aruaru-llm Translate / Generate / Ocr) at the default `https://maid-cafe.tokyo`, the open-english server (behind the maid-cafe.tokyo front, 127.0.0.1:8104) gained a versionless Connect gate `POST /openenglish.AiGate/<Method>` (`server/src/ai_gate.rs`). No new REST. aruaru-llm (127.0.0.1:4600) stays private; only these three methods are forwarded through the gate (`/aruaru_llm.Llm/*` from the front is 404).
- Login: `RequestOtp {email}` → e-mailed code → `VerifyOtp {email, code}` → an AI-only token (7 days, `Authorization: Bearer`). Issuing and checking reuse `auth.rs` (`request_otp_any` only drops the admin-only check). It never issues a normal login session, so it cannot bypass the admin two-step login. Tokens live in memory and vanish on restart (log in again).
- Admission: MemAvailable from `/proc/meminfo` every 2 s; every 10 s the concurrency limit adapts (halve below 350 MB free; +1 above 700 MB when saturated and responses are under 60 s; max 4). Below 200 MB new requests get 503 + Retry-After at once; over the limit they queue (8 people, 20 s) and overflow gets 503. **The "AI" part is only this rule-based feedback control (AIMD), not machine learning.** It joins aruaru-llm's fair queue with `x-tenant: maid-cafe-vsc`. Tunable via `AI_GATE_*`.
- Translate worker: M2M100 418M int8 (MIT) runs as `aruaru-translate.service` (127.0.0.1:4620, 2 threads, MemoryMax=900M); aruaru-llm gets `ARUARU_TRANSLATE_URL` via drop-in `30-translate.conf`. Measured: worker RSS about 670 MB, free memory afterwards about 730-1000 MB, about 1.5 s per sentence.
- Production checks (2026-11-27): 401 for all four methods without login, 401 with a fake token, `.v1` 404, `aruaru_llm.Llm/*` from the front 404, every domain answers exactly as before the swap, no error logs. The logged-in flow (OTP → token → Translate returned a real Japanese translation, Generate 200, empty Ocr 400, 503 + Retry-After at the memory threshold, limit 1 / queue 1 with 4 concurrent → 503×3 / 200×1) was verified with the same binary run temporarily on the VPS loopback only, using the dev code print that works only when SMTP is not configured. **Receiving a real OTP e-mail needs a person and is unverified.** Old binary: `open-english-server.before-aigate-20261127`.
- Incident note: the first temporary run from `/root` let the built-in component updater (`component_update.rs`) treat `/root/aruaru-llm` (a link to the repo) as its own component and stop production aruaru-llm three times (systemd restarted it; no files were overwritten; temp files removed). Run test instances from a dedicated folder without component folders.

## 2026-11-27 AI入口のトークンを再起動後も有効に / AiGate tokens survive restarts
**日本語**: `/openenglish.AiGate/*` のログイントークンはメモリだけに保存され、サーバー再起動で消えていた。トークンの **SHA-256 だけ**を JSON(DB と同じ `data/` の `ai-gate-tokens.json`、権限600、一時ファイル→置き換えで保存)へ書き、起動時に期限内のものだけ読み込むよう修正(期限7日は従来どおり、平文はディスクに書かない、`OPEN_ENGLISH_AI_GATE_TOKENS` で場所を変更可)。試験を追加(ハッシュのみ保存・権限600・読み直し・期限切れは読まない)、あわせて未宣言だった AiGate ルートを API 文書へ追加し `cargo test` 111件成功。本番(`open-english`・`open-english-demo`)へバックアップ `open-english-server.before-tokenpersist-20261127` 付きで入れ替え、未ログイン/不正トークン401・各ドメインの応答が入れ替え前と同じ・エラーログ0を実測。**未確認**: 実際にOTPでログインして再起動後もトークンが使えることの本番での通し(本人のOTPが要る)。
